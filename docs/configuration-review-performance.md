# 大配置审阅的性能边界与验证

配置审阅页面默认请求 `/api/config/diff?view=preview` 和 `/api/config/versions?view=preview`。每份展示文本经过服务端脱敏，再限制到 **16 KiB 或 200 行**，取先到达的边界。前端也做展示限制，使用不换行的可滚动文本容器。超过限制时明确标注为片段；片段不保证是完整 JSON。

`changed`、原始字节数、SHA-256 摘要、语法校验、应用和回滚始终使用完整配置。默认不带 `view=preview` 的接口仍返回完整内容，兼容既有客户端。当前与候选原文一致时，diff 接口复用一次脱敏结果。

完整内容通过 `/api/config/download?source=current|candidate|previous&hash=<预览摘要>` 下载。该接口沿用登录保护，校验来源与摘要，返回 `no-store` 的 JSON 附件；摘要过期返回 409，需刷新预览。浏览器直接保存文件，不将大文件再放入 React 状态或页面 DOM。下载仍包含脱敏标记，**仅供审阅，不是可直接运行的配置备份**。无效 JSON 无法安全脱敏，因此拒绝下载。

采用有界预览和按需附件，可以同时限制初始传输、浏览器 JSON 解码、DOM 文本量和布局成本。虚拟列表只能解决部分布局成本，还需处理超长单行和完整载荷；本次没有引入这套额外机制。

## 本地证据（2026-10-16）

环境：Apple M4 Pro、隔离 Chromium 155.0.8059.80、1440×1000、生产构建。基线前端为 `ee8986f`；前后对比使用同一合成数据和真实 API，后端为本次实现（基线前端请求兼容的完整响应）。另在修改后端前确认过 7,033,046 字节配置的原始 diff、versions 响应各约 15.15 MB，服务端请求分别约 203 ms、147 ms。

测量在导航前启用 CDP Performance 和 `PerformanceObserver(longtask)`，记录首次两栏绘制完成时的指标；只对 JSON 解析耗时和字节数做记录，不在测量期间执行全文 DOMSnapshot。下表是单次本地观测，不是跨设备性能保证。MB 使用十进制。

| 合成配置原始字节数 | 旧页面布局耗时 | 新页面布局耗时 | 旧页面最长长任务 | 新页面超过 50 ms 的长任务 | 两个审阅接口响应总量：旧 → 新 |
| --- | ---: | ---: | ---: | --- | ---: |
| 3,289,046 | 923 ms | 8.3 ms | 978 ms | 无 | 14.17 MB → 33.1 KB |
| 32,773,046 | 8,772 ms | 6.8 ms | 9,349 ms | 无 | 141.18 MB → 33.1 KB |

3.29 MB 配置的两次浏览器 JSON 解析各约 7.2 ms；32.77 MB 配置分别约 71 ms、65 ms。相比之下，完整 `<pre>` 的布局成本明显更大。旧页面每栏分别布局约 151 万、1,503 万像素高的文本，`max-height` 并未限制布局工作。这是本地复现中的主要瓶颈，重复完整载荷是额外开销。

附加覆盖：

- 13,670 字节普通配置：布局约 6.4 ms，无长任务。
- 23,528,149 字节紧凑单行 CURRENT / 32,773,046 字节 CANDIDATE：布局约 5.3 ms，无长任务；原文不同仍显示 PENDING CHANGES。
- 30,013,076 字节配置，包含两处各 15,000,000 字符的单条规则字符串：每栏最多 16,384 字符，布局约 5.2 ms，无长任务。验证了横向滚动和导航（约 151 ms）。浏览器下载为 30,013,076 字节有效 JSON，两处超长字符串均完整保留。
- 多规则配置验证纵向滚动、导航（约 149 ms）、打开并取消历史恢复窗口、调用假内核校验、刷新后清除旧校验状态，以及浏览器完整附件下载。
- 窄屏 390×844 检查页面、滚动与历史恢复窗口；没有执行真实应用或回滚。

上述数据支持完整文本布局是可信的卡顿原因，但没有重现现场 `RESULT_CODE_HUNG`，也不排除现场扩展、自动化读取或设备资源放大影响。未访问家庭网关；现场文件精确字节数未再次核对，本地 3,289,046 字节样本不代表现场文件大小。

## 重现方法

```sh
npm --prefix web run build
SBM_CONFIG_REVIEW_WEB_DIR="$PWD/web/dist" \
  go test ./internal/api -run '^TestConfigurationBrowserFixture$' -v -timeout 30m
```

测试打印随机回环端口。在浏览器打开该端口的 `/__fixture?case=3mb`，再进入 `/configuration`。可选 `small`、`3mb`、`30mb`、`compact`、`long-line`。夹具使用临时数据目录和假内核，不启动 sing-box、调度器或网关辅助服务；只有显式设置环境变量才启动，最长运行 20 分钟。不要将其对外暴露。切换前端构建后重新加载页面，避免旧页面引用已删除的资源文件。

```sh
go test ./internal/api -run '^TestConfig(Preview|Review)' -count=1
go test ./internal/api -run '^$' -bench '^BenchmarkConfigReviewPayload$' -benchtime=1x
go test ./...
go test -race ./...
go vet ./...
node --test web/src/**/*.test.mjs
npm --prefix web run build
```

本次上述检查通过。改动文件 ESLint 通过；全量 ESLint 的 30 个错误、2 个警告与提取出的 `HEAD` 基线完全一致。

剩余边界：服务端仍完整构建、解析和脱敏配置，下载也是完整内容，CPU/内存成本仍随配置增长；本次未引入流式脱敏或跨请求缓存。历史接口、共享设置接口及其他配置页面未全面改成有界载荷。浏览器测试使用假内核，只证明审阅和交互路径，不替代真实内核、部署或家庭网络验收。
