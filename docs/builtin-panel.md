# 内置运行面板

代理、连接、流量和日志均通过已登录的管理服务访问。浏览器无需连接内核端口或填写 Clash API 密钥。现有订阅、节点、分流规则、部署与配置审阅继续使用原有入口。

## 从外部面板迁移

- 新生成配置保留 `experimental.clash_api` 和选择缓存，但移除 `external_ui` 与下载 URL；控制 API 固定监听 `127.0.0.1`，与 mixed 的 LAN 访问开关独立。旧 `clash_ui_path` 字段继续可读，不再用于生成配置，已有面板目录和缓存文件不删除。
- 仅升级管理器不会改写运行配置。通过现有配置审阅、检查和应用流程采用新配置；正在运行的内核会按既有健康检查与失败恢复流程重启。没有自动升级内核、改动路由接管或更改规则的步骤。
- 旧管理器保存的运行身份没有配置摘要时，新运行面板会提示通过服务页重启。只靠修改草案端口或密钥不能转向另一个内核。
- 设置中的内核控制端口为 `0` 时停用运行控制；页面明确显示不可用。旧版/裁剪内核未提供相应 Clash API 时提示不支持，不伪造正常空结果。
- zashboard 已在 3.23.0 移除 sing-box 支持。内置页面不再依赖其最新版本，也不复制其规则/全局/直连模式按钮。

## 局域网代理与配置生效

“允许局域网外部设备访问”控制 HTTP/SOCKS 的 mixed 入站：单机、完整网关和 DNS 分流旁路模式均在开启后监听 `0.0.0.0:<mixed_port>`，关闭后仅监听 `127.0.0.1:<mixed_port>`。其他设备应使用代理主机的 LAN 地址和 mixed 端口，例如 `192.168.31.31:3712`；`0.0.0.0` 是监听范围，不是客户端填写的地址。

Web 管理端口（默认 `9090`）和内核控制端口（默认 `9091`）都不是 HTTP/SOCKS 代理端口。内核控制接口保持本机监听不影响局域网代理或内置连接页。

关闭“配置变更后自动原子应用”时，保存设置仅更新草案，还需在“配置管理”审阅并应用才会更新运行中的入站。生成配置由管理器维护，直接编辑生成文件会在后续应用时被重新生成；修改运行文件也会触发配置摘要校验，使运行面板提示配置变化。

## 代理与连接

代理页从正在运行的内核读取代理组、当前成员与延迟。selector 可以手动切换；urltest 展示自动选择并支持测试。嵌套组显示最终选择链，特殊名称（包括中文、斜杠和百分号）保留原名。支持搜索、排序、折叠、隐藏与恢复。

热切换不生成/应用配置，不重启内核。操作后回读真实选择；只在一致时报告成功。已有连接是否中断由该组的内核配置决定，面板不会默认关闭全部连接。选择由内核缓存持久化，节点被订阅移除后的回退由内核决定并重新显示真实选择。

手动测速使用浏览器偏好中的 HTTPS URL 与超时，与自动测速组的周期配置分开。全服务最多 4 个并发探测；一次最多 512 个展开后的叶节点，整体上限 90 秒，超时/不可达不显示为 0ms。地址预检查拒绝明显的内网目标，并兼容域名经本项目 FakeIP 池返回的地址；这不是 DNS 固定绑定，内核仍自行解析和处理跳转，因此应使用可信的稳定 HTTPS 测试服务。

连接页只反映流经当前 sing-box 的活动连接，不代表全网流量。提供来源、目标、代理链和协议筛选，流量/速率排序、详情、分页、列显示与列宽。内核缺失的字段显示为 `—`。速率来自两次快照差值，重启或计数器回退后重新采样。

页面可以直接选择 1 / 2 / 5 秒刷新。已采样的连接离开活动列表后移至“最近结束”，保留最近 5 分钟、最多 1000 条，仅驻留页面内存；离开页面或内核实例变化时清空。结束时间是首次观察到连接不再活动的时间，流量保留最后一次活动采样值，不代表精确结束时间或最终流量。最近结束的记录不计入活动数量，也不能执行关闭操作。

Clash API 返回当前活动快照，短于采样间隔的连接可能完全落在两次查询之间；“最近结束”不能补回从未采样到的连接，也不是完整访问审计。接口读取失败时保留旧快照并提示错误，不把查询失败显示成正常零连接。如果持续下载仍完全不可见，应核对连接页错误提示、`/api/runtime/connections` 的响应及受管内核日志；直接修改运行配置可能触发摘要不匹配，此时流量仍可继续，但运行接口会明确返回配置变化错误。

关闭单条、筛选结果、全部或某代理组连接时，确认框固定捕获连接 ID 与实例标识。确认后新增的连接不受影响，不调用有额外网络重置行为的内核“全部关闭”接口。批量结果区分已关闭、已结束和失败；跨批次失败保留已确认数量，刷新实际状态，不自动改到新实例重试。

运行操作与进程生命周期协调：在途请求结束前不替换实例，排队操作必须重新验证实例；应用/重启期间明确显示暂不可用。管理器只访问匹配启动身份和配置摘要的本机内核，不提供任意 URL 反向代理。

## 日志和设置

### 编辑导入规则

分流规则表中的“导入”规则可直接点“编辑”，在原规则中修改域名、域名后缀/关键字、IP、来源、端口、协议、引用规则集，以及普通路由/拒绝动作和目标出站，无需重新导入。只提交修改的字段，保留原顺序、逻辑子规则和未编辑的扩展参数；高级动作及连接处理参数不由普通动作下拉框改写。远程规则集的内容仍由上游维护，编辑的是规则集引用，界面提供来源链接。

保存前核对整个导入策略版本，重新导入或其他页面编辑导致版本改变时拒绝覆盖；验证匹配字段、规则集及出站引用，已安装内核时进一步执行配置检查。验证失败不写入原规则；通过后沿用自动应用设置，应用失败显示“已保存但应用失败”。重新导入整份配置可能替换这些本地编辑。

自定义和导入规则均可点击“删除”，确认后移除整条规则；其流量继续匹配后续规则或默认出站。导入规则删除同样检查策略版本及候选配置，保留其余规则次序、规则集和出站。开启自动应用时，删除会校验并应用配置，自动重启正在运行的 sing-box；关闭时须点击“检查与应用”，应用流程负责重启。已停止的内核不会自动启动，尚未启用的网关也不会因删除而启用。自动应用失败时删除仍已保存，界面提示检查并应用；预设规则组通过开关停用。

### DNS 查询记录

侧栏“DNS 查询记录”提供独立的域名汇总和查询明细，可按来源 IP、域名关键字、查询类型和时间筛选，复制候选域名或导出最近最多 10000 条匹配查询的 CSV。定位广告时先选目标设备、打开应用复现广告，再查看对应时间段；频繁出现的域名不自动视为广告，也不会自动修改拦截规则。

域名汇总默认按最近查询排序，也可切换为次数优先。首次加载建立对照，后续轮询发现的新请求以蓝色行背景和“新增”标签提示；汇总中的标签表示该域名有新查询，并非首次出现的域名。标记持续到点击“标为已读”，切换筛选、视图、排序或翻页重新建立对照。暂停仅停止页面轮询，恢复后仍比较新请求。

“下载规则库 / 更新规则库”从 [anti-AD 官方仓库](https://github.com/privacy-protection-tools/anti-AD) 下载公开的 Surge 格式域名列表，保存到管理器数据目录 `domain-lists/anti-ad.txt`，重启后继续使用；仅手动更新，超过 7 天提示过期。下载有 20 秒超时和 8 MiB 上限，校验规则格式与声明条数，失败保留上次完整版本。匹配只在管理器本地完成，不发送采集域名给规则库；完整域名和后缀规则按各自语义匹配。

列表显示“疑似广告 / 跟踪”“未命中”或“待比对”，点击可查看命中规则、库版本和本地更新时间，并查询域名用途或 VirusTotal 安全信誉。anti-AD 同时覆盖广告、统计和部分日志收集；命中仅是辅助依据，不等于广告请求或已被拦截，未命中也不代表安全。外部查询仅在点击时将对应域名交给目标网站。这些功能不会自动修改分流规则或应用内核配置。

域名行和详情弹窗提供“拦截”，将完整域名加入“自定义域名拦截”集合；只精确匹配填写的域名，不扩大到主域及其他子域。DNS 页和分流规则页均有“编辑拦截集合”，可按行增删域名、停用集合；清空列表会移除自定义规则，不生成无条件拒绝。集合使用原有自定义规则存储，与上游广告库独立，更新广告库不会覆盖补充内容。

追加操作在后端串行合并、规范化和去重，最多 5000 个域名；编辑保存校验读取时的版本，冲突时保留输入并提示重新载入。已停用或改成其他匹配条件的集合不会被“一键拦截”擅自启用或扩大。新集合位于已有自定义规则之前，但设备策略、hosts 等更高层规则仍保持既有顺序。

拦截集合保存沿用自动应用设置，可能短暂重启运行内核；应用失败明确提示已保存但未应用。“已加入”仅表示存在自定义规则，不证明某次请求已拦截。查询记录包含被拒绝的请求，不能用域名是否出现在记录中判断访问成功，也不能凭命中 anti-AD 就报告拦截成功。

采集默认关闭。开启后将内核实际日志级别提高到至少 `debug`，保留原先选择的输出级别，关闭后恢复。设置按既有自动应用开关处理：自动应用开启时保存会应用并短暂重启运行内核；否则保存草案后需在配置审阅手动应用。页面会显示待应用、写入错误和日志接续缺口，不将空结果当作采集正常的证明。

后台每 5 秒增量读取内核日志，归档 `lan-dns` 入站的实际查询事件，包含时间、原始来源 IP、域名和查询类型。普通内部解析不混入终端记录；已拒绝的 DNS 查询也可记录。来源上下文、查询和读取游标在同一归档帧同步提交，管理器重启后恢复并续接；页面关闭或暂停刷新不停止后台采集。首次从现有内核日志尾部接入，不补录此前所有历史。日志轮转超出保留范围时明确记录缺口。

数据位于管理器数据目录的 `dns-queries/`，目录权限 `0700`，文件权限 `0600`，与一般日志独立。可查询最近 7 天，最多 100000 条；归档按最多 16 个 4 MiB 数据段轮转，并清理过期段和超量记录。混合新旧查询的数据段随轮转清理，整段过期后即使没有新查询也会清理，保留读取游标。接口及 CSV 导出要求登录、沿用来源限制和写请求保护，返回 `Cache-Control: no-store`；导出包含公式前缀防护。

这不是抓包或 HTTPS 解密。仅记录确实经过家庭 LAN DNS 的有效查询；终端缓存、自带 DoH、其他 DNS 或 VPN 内部查询仍可能不可见。主路由代转 DNS 时只能记录实际可见的路由器来源。归档不推断广告、是否成功访问或拦截结果，也不改变监听、FakeIP、设备策略和分流规则。

日志保留独立中继、落盘、10 MiB 轮转和 3 份备份。新增 SSE 增量读取，游标绑定日志来源、文件身份和字节位置，轮转后续读；历史已超出保留范围时显示缺失提示。流持续验证登录状态，退出或到期后断开。

日志页支持内核/管理器来源、级别/关键词过滤、暂停与恢复、跟随、清屏和脱敏导出。清屏只清显示，不删除文件；游标保留在当前标签页的 sessionStorage，刷新后不重新显示已清内容。页面缓存上限可选，另有 4 MiB 字符缓存限制。导出最近最多 1000 行，尾部读取上限 256 KiB；不是完整历史归档。

刷新频率、节点排序、折叠/隐藏、测速地址/超时、连接列/列宽、日志缓存/跟随保存于浏览器，不应用内核配置。内核日志输出级别保存于管理器配置，默认 `info`，按现有自动应用设置生效；应用到运行实例会重启。日志页的级别过滤只影响显示。

## 验证

```sh
go test ./...
go test -race ./...
go vet ./...
npm --prefix web run build
cd web && node --test src/utils/*.test.mjs
```

真实内核验收使用官方二进制的绝对路径：

```sh
SBM_TEST_SINGBOX=/isolated/path/sing-box go test -race ./internal/runtimecontrol -run TestSingBoxIntegration -v
SBM_TEST_SINGBOX=/isolated/path/sing-box go test ./internal/builder -run TestRealKernelGeneratedConfigurations -v
SBM_TEST_SINGBOX=/isolated/path/sing-box go test ./internal/dnsquery -run TestRealKernelDNSQueryJournal -v
```

集成测试只使用临时目录、回环高端口和本地受控 HTTP 出口，不启动 TUN、不修改系统路由。它验证热切换 PID 不变、新连接实际走新出口、旧连接保留、指定关闭不影响另一连接，以及重启后的选择恢复。页面交互、窄屏和深浅主题仍须另做真实浏览器验收。
