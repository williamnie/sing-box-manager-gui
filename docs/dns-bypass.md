# DNS 分流旁路

DNS 分流旁路保持终端默认网关指向主路由。可以只在需要接入的终端上手动指定旁路设备为 DNS，也可以由主路由 LAN / DHCP 统一下发。终端无需预先添加到“设备与策略”；未配置单独策略的终端按默认规则分流。代理域名由旁路 DNS 返回 FakeIP，主路由再按静态路由将 FakeIP 连接送到旁路设备。国内直连域名返回真实地址，连接继续经主路由；内网 hosts / Split DNS 优先解析内网地址。

这要求终端**使用旁路 DNS**，以及主路由具有 **FakeIP 网段到旁路地址的静态路由**。已有路由可以复用；仅修改 DNS 而缺少静态路由时不能工作。按设备接入时不必修改全网 DHCP。检查终端实际生效的完整 DNS 列表，包括备用 IPv4 DNS、IPv6 通告的 DNS、系统私人 DNS 和浏览器安全 DNS；只填写 DNS 1 并不保证其他解析器已经移除。

“部署与设备 → 设备与策略”中的“最近接入设备”根据活动连接和近期 DNS / 代理日志自动显示来源 IP，不会自动修改策略。只有需要直连、绕过等单独策略时才添加配置。来源观察最多保留 512 项和 24 小时，管理器重启后从有界日志尾部恢复；它不是永久资产清单，也不是接入白名单。提高日志级别可能使仅 DNS 客户端暂不可见，未出现在列表不影响接入。

本文地址 `192.0.2.0/24` 为文档保留地址，部署时替换为实际网络。示例主路由为 `192.0.2.1`，旁路为 `192.0.2.2`，终端为 `192.0.2.20`，不是产品默认值。

## 与其他模式的区别

| 项目 | 单机 | DNS 分流旁路 | 完整网关接管 |
| --- | --- | --- | --- |
| 部署字段 | `desktop` | `gateway`，`access_mode=dns` | `gateway`，`access_mode=full` |
| 支持系统 | macOS / Linux | Linux | Linux |
| 终端默认网关 | 不涉及其他终端 | 保持主路由 | 指向旁路设备 |
| LAN 接入 | 无 | LAN DNS 53 + 限定 FakeIP 的 TProxy 9898 | LAN DNS + TUN 自动接管 |
| DHCP | 无 | 继续由主路由提供 | 可选专用 DHCP |
| 转发与 NAT | 不调用家庭接管 helper | 不无条件开启整机转发，不做 NAT | 按拓扑启用受管转发，可选 NAT |
| IPv6 | 既有单机行为 | 无 IPv6 FakeIP 接管，代理域名所有非 A 类型返回空应答 | 可按拓扑接管 IPv6 |
| 严格全代理设备 | 既有行为 | 拒绝应用 | 保留原严格策略语义 |

旧 `gateway` 配置缺少 `access_mode` 时按 `full` 处理，升级不会静默变成 DNS 旁路。单机的 mixed / TUN、订阅、规则和通用导入入口保留。

## 配置步骤

1. 按 [Linux 网关安装说明](linux-gateway.md#初始化)准备独立 Linux 实例、管理器和 helper。为旁路设备保留固定 LAN 地址。helper 的 root 策略须同时允许 `allow_gateway` 和 `allow_dns_bypass`，并授权实际 LAN / 上联接口、来源网段；旧策略不会自动取得新能力。不要把管理页面开放为未鉴权的 LAN 明文服务。
2. 在“部署与设备”选择“家庭接入（Linux）→ DNS 分流旁路”。填写 LAN 地址、接口、LAN 来源网段、上联接口和真实默认网关。模式不需要开启单机 TUN、NAT、DHCP 或 IPv6 接管。
3. 设置 FakeIP 地址池。默认 `198.18.0.0/15`，可选其中 `/15` 至 `/24` 的规范 IPv4 子网，不能与 LAN 或排除网段重叠。主路由配置静态路由 `198.18.0.0/15 → 192.0.2.2`（按实际池和旁路地址替换），并在向导中确认路由存在。更改旁路地址或池后需重新确认。
4. 在主路由 LAN / DHCP 中将 DNS 地址设为旁路地址 `192.0.2.2`，默认网关继续下发主路由 `192.0.2.1`。建议选择“DHCP 直接下发旁路 DNS”，确保旁路收到终端原始 DNS 来源。不要把另一个可直连解析器作为未经规划的备用 DNS，否则终端可能绕过分流。
5. 在设置页核对直连 DNS、代理 DNS 和 hosts，在部署页核对 Split DNS 与设备分组，在规则页核对“匹配流量 → 处理方式”。普通设备选普通分流。需要对设备作直连例外时，在主路由保留其地址，并在设备来源中配置对应 IP / CIDR。
6. 保存草案，审阅预览，执行启用前检查，再确认启用。草案保存不代表接管已启用；页首分别显示两者。检查验证本机能力和资源，静态路由确认仍需在主路由核实。冲突必须处理或改用独立环境，管理器不会自动停止现有 DNS、TProxy 或其他实例。
7. 等待 DHCP 租约更新，或让测试终端重新获取网络配置。核对 DNS 已变成旁路地址，而默认网关保持主路由；按下方清单验收后扩大使用范围。主路由设置更新通常统一作用于正常 DHCP 终端，无需逐台改网关。

若旧实例正在使用相同 DNS / TProxy、接管表或策略路由，先安排切换窗口与回退。不能让两个接管实例并行争抢资源。离线开发或隔离验证不需要改动现网。

## DNS 来源、设备与规则

### 迁移已有真实 IP 透明流量

已有主路由可能还会把 Telegram 等真实公网 IP 转交给旁路，而不只是转交 FakeIP。此时须在“局域网 DNS”中启用 `capture_routed_traffic`（接收主路由转交的公网 IP 流量），并在 root helper 策略中显式允许 `allow_routed_traffic`。两项默认均关闭，升级不会自动扩大接管范围。

开启后仍只处理配置的 LAN 接口和 LAN 来源：FakeIP 路径保留，额外接收已经到达本机的公网 IPv4 TCP/UDP；排除本机、内网、组播、配置的排除网段和 UDP 53/123/5354。真实 IP 流量按原有目的 IP、协议、端口与出站规则处理，不会强制全部走同一个代理。它不修改主路由，不接管宿主 OUTPUT，不打开全局转发/NAT，也不自动提供 IPv6 透明代理。

此时表 `20230` 使用到 `lo` 的 `local default`，仅限专用策略表；策略规则仍要求 LAN 入口和完整 mark `0x5342`。主表默认路由不变。切换接管范围前必须先恢复旧计划；同样检查 root 授权、归属、重复应用、资源漂移与重启恢复。已被主路由转交的真实 IP 连接在停止本服务时同样会中断，不能假设它们自动退回主路由直连。

“DHCP 直接下发旁路 DNS”保留来源地址，可实现不同终端的真实地址 / FakeIP 策略。DNS 来源仍需结合真实网络确认，NAT 或其他 DNS 转发器可能合并地址。LAN IP 来源并不等价于交换机端口认证。

选择“主路由作为 DNS 转发器”时，DNS 包来源可能全部变为路由器。系统明确拒绝与其不兼容的设备来源策略、来源限定 Split DNS 和来源差异规则；不能假装仍能按终端区分 DNS。需要设备差异时，应改为 DHCP 直接下发旁路 DNS，而非在此模式添加无法生效的来源条目。

路由器提供替代 DNS、使用自身缓存或转发到其他解析器时，不能保证终端获得本实例当前策略的答案。旁路关闭应答缓存不会清除路由器或终端缓存；须验证设备确实使用这条 DNS 路径，必要时按路由器维护方式更新缓存与租约。

DNS 决策优先遵循 hosts、设备直连 / 绕过、Split DNS，然后按可安全转换的自定义、预设及导入域名规则与最终出站处理。普通国内直连规则返回真实地址，代理域名的 A 查询使用 FakeIP。规则里出现目标端口、TCP / UDP、嗅探协议等 DNS 无法判断的条件时，不把其扩大成覆盖整个域名的 DNS 条件；这些流量规则仍保留，并仅在连接实际进入实例后匹配。

FakeIP 恢复为域名后，`resolve` 等内部业务查询通过配置的代理 DNS 获取真实地址，不能统一送到直连 DNS，否则被污染的真实 IP 会继续传给代理节点，表现为部分域名已命中代理仍然超时。节点服务器地址和直连出站的显式 `default_domain_resolver` 仍使用直连 DNS，避免代理 DNS 依赖自身建立连接的循环。此调整不改变 LAN 客户端的 FakeIP、直连、hosts 或设备策略。

动态选择组同时包含直连和代理选项时，DNS 返回 FakeIP，以便后续选择代理仍能将连接送入实例；选择 `DIRECT` 后，连接在旁路解析并直连，不能据此期待终端恢复为直接经主路由出网。明确直连 / 拒绝的预设组与最终策略按已保存出站生成，修改后需重新应用。导入的不透明远端规则集只保留流量匹配，不根据标签名称猜测其中是否全是域名并扩大 DNS 分流。

设备直连 / 绕过优先返回真实 DNS 地址，正常连接继续经主路由。设备策略变更后，若终端仍持有旧 FakeIP，实例保留受限接收，并按当前来源策略直连恢复的域名。严格全代理无法覆盖 DNS 旁路之外的连接，因此 DNS 模式拒绝含严格分组的草案，需主动调整分组或选择完整网关；不会静默改变完整网关的严格策略。

独立来源限定 STUN 规则继续保留，只对实际进入实例且能嗅探识别的 STUN 生效；不把所有 UDP、宽泛端口范围或 BT / PT 强制代理。BT / PT 的直接 IP 连接和返回真实地址的域名连接继续经主路由。Docker bridge NAT 可能只暴露宿主来源，需要容器差异时应先提供可识别的独立网络地址。

来源无关的配置导入和既有 `ImportedPolicy` 数据保留。DNS 旁路会检查导入 DNS 与路由能否安全转换；复杂或不受支持的语义会明确阻止应用，不能静默删除导入策略来过检查。调整前应保留导入原文件和恢复点。

导入策略先按业务流量规则选择直连或代理分支，再在该分支内依原 DNS 规则次序选择解析器，来源和域名条件取交集。真实 DNS 上游的地址、协议或 `detour` 不代表业务流量应直连；代理分支仍返回 FakeIP。直连分支保留原真实上游、解析策略和 TTL；明确的 hosts、FakeIP 与拒绝 DNS 规则保留其匹配约束。管理器自己的 hosts、设备和 Split DNS 仍优先。组合展开超过 10000 项会拒绝并提示精简，避免导入导致失控的配置膨胀。

## IPv6 与覆盖边界

当前模式只提供 IPv4 FakeIP。代理域名**仅 A 查询返回 FakeIP**，所有其他类型（包括 AAAA、HTTPS / SVCB、ANY、TXT、MX、SRV）均返回 `NOERROR` 空应答，避免真实 IPv6、IP hints 以及 ANY 或 MX / SRV 附加区中的真实地址绕行。这会影响依赖 TXT / MX / SRV 等记录的应用；需要这些记录的域名应显式选择直连规则或直连 Split DNS。

hosts、直连 Split DNS 及普通直连域名保留正常非 A 解析，仍可返回真实 IPv6；本模式不禁止主机或 LAN 的全部 IPv6，也不发布 IPv6 路由或 RA。

硬编码 IP、应用自带 DoH / 其他 DNS、已缓存真实地址、IPv6 备用路由、另一张网卡或移动网络可能直接经过主路由。DNS 分流不能保证所有流量都进入实例，也不能保证只改 DNS 就实现 WebRTC 零泄露。需要完整覆盖时，应选择完整网关，并另行核实 IPv4 / IPv6 和所有实际出网路径。

## 缓存、重启与模式切换

DNS 应答缓存关闭（`disable_cache=true`），避免一个设备 / 分组的答案被另一个来源复用。FakeIP 域名映射是另一项独立持久化数据，存放在本实例的 `dns-bypass-<池的 16 位 SHA-256>.db`；正常内核重启保留映射。同一池共享域名身份映射，但不缓存来源策略决策；更新策略不主动清空已有映射，已缓存 FakeIP 的连接仍按当前来源和路由规则处理。不要让两个实例共用数据或缓存目录。

变更 FakeIP 地址池会隔离旧池映射。先恢复当前接管，修改主路由静态路由与草案，重新检查、应用，再让终端更新 DNS 缓存。主路由路由和终端仍缓存的旧池地址不会被管理器自动修改；不能假定重启内核可以清除终端缓存。不要在实例运行时手工删除映射数据库。

在仪表盘**显式停止**内核时，DNS 旁路同时恢复 helper 自有资源，将 `Gateway.Enabled` 设为 `false`，并保持内核进程停止。再次使用必须在部署页重新检查并显式启用，不能把普通“启动”当作重新安装接管资源。进程**异常退出**仍保留所属资源记录，供状态检查与显式恢复，不能假定已经自动撤回网络计划。

停止后 FakeIP 代理连接与本实例 DNS 不可用，已知真实 IP 连接仍按原主路由路径运行；这不代表严格断网保护。正常重启内核保留映射并重新做健康检查。helper 记录自有资源和 boot ID；主机重启后需按恢复流程处理旧启动状态，再检查并显式应用，不凭旧记录自动重放接管。

DNS 旁路与完整网关互斥。切换前安排主路由 DNS / 静态路由和客户端缓存回退，执行“恢复接管资源”，再选择新的模式。完整网关切换还需处理终端默认网关。恢复只撤回本项目所属资源，不修改主路由、终端、其他 nftables 表或 Docker 配置，不执行全局 flush。

## 特权资源与验证

LAN DNS 仅监听配置的 LAN 地址与标准 TCP / UDP 53；受限 TProxy 使用 9898。默认只接收配置的 LAN 接口、受管来源、FakeIP 目标的 TCP / UDP；显式兼容接管的差异见上节。不创建全局 `auto_route` / `auto_redirect`，不改写宿主或 Docker 的普通目标路由。helper 校验归属、端口、表 / 标记 / 路由冲突与资源漂移。其权限不等同于允许管理器执行任意系统命令。

当前所属资源为 `inet sbm_gateway`、标记 `0x5342`、IPv4 路由表 `20230`、优先级 `12030` 的策略规则与协议标识 `242`。策略规则同时限定入口、FakeIP 目标与完整标记，表中只存在对应池到 `lo` 的本地路由；预览的 `policy_routes` 展示将生成的两条 `ip` 命令。DNS 模式仅将 LAN 接口 `rp_filter` 调整为 loose（`2`），保存原值用于恢复，不打开全局 forwarding，也不套用完整网关的全部 sysctl。已有同名 / 同标记资源无法证明所属时拒绝接管。

预览不执行网络修改；检查、显式应用、重复应用、健康状态与恢复都走现有特权边界。失败应保留可恢复事务，存在未完成事务或外部漂移时先恢复与核查，不能覆盖未知资源。两模式使用不同网络计划，DNS 模式不套用完整网关的全部 sysctl 和 NAT / DHCP 行为。

在隔离 Linux 网络中至少验证以下项目，真实家庭验收须另行安排：

| 用例 | 应观察到的结果 |
| --- | --- |
| DHCP 终端 | DNS 是旁路，默认网关仍是主路由 |
| 国内直连域名 | 返回真实 A / 可用的 AAAA，连接从主路由直连 |
| 代理域名 | A 在配置 FakeIP 池内，所有非 A 类型均为 NOERROR 空答；TCP 和 UDP 经受限 TProxy |
| 非 A 记录例外 | 显式直连 / 直连 Split DNS 域名可查询所需 TXT / MX / SRV，hosts 保持原有行为 |
| 内网 hosts / Split DNS | 返回配置的真实内网地址，可正常访问 |
| 两个不同设备交替查询相同域名 | 直连 / 普通分流的结果按各自策略计算，不受对方缓存影响 |
| 路由器转发 DNS + 来源差异 | 检查明确拒绝；不伪称终端已识别 |
| 严格全代理设备 | DNS 模式明确拒绝；完整网关回归保持原语义 |
| 重启内核 | 同池映射持续可用，配置健康检查通过 |
| 显式停止 | helper 资源恢复，启用状态关闭，进程保持停止；重新使用须检查并启用 |
| 异常退出与失败恢复 | 所属记录保留供检查恢复，不扩大为全局接管，已知真实 IP 路径仍归主路由 |
| 重复应用 / 冲突 / 模式切换 | 不叠加资源，冲突被拒绝，恢复后才能切换 |
| 普通 UDP、BT / PT、宿主及 Docker | 没有因宽泛 UDP / 端口或全局路由被新增强制代理 |
