# 部署角色、登录与配置管理

## 支持范围

| 系统 | 部署角色 | 接管方式 |
| --- | --- | --- |
| macOS | 单机 `desktop` | 原有 mixed、可选 TUN、launchd |
| Linux | 单机 `desktop` | mixed、可选 TUN、用户级 systemd |
| Linux | 家庭接入 `gateway` + `access_mode=dns` | DNS 分流旁路：独立 LAN DNS，限定 FakeIP 目标的 TCP / UDP TProxy；终端默认网关不变 |
| Linux | 家庭接入 `gateway` + `access_mode=full` | 完整网关接管：独立 LAN DNS、TUN + auto_route + auto_redirect；终端默认网关指向本机 |

旧数据升级至 schema 2，未配置部署角色时保持单机，保留 TUN、mixed、订阅和规则。既有 `gateway` 的空 `access_mode` 归一化为 `full`，不会静默切换为 DNS 旁路；系统为 Linux 不会自动选择或启用家庭接管。macOS 可离线预览 Linux 草案，不能执行网关系统操作。数据目录仍是一个实例的边界，配置固定在 `generated/config.json`，内核固定在 `bin/sing-box`；API 不接受任意可执行程序或写文件路径。不同实例必须使用不同数据目录和端口。

DNS 分流旁路的正常用法是：终端自动获取地址和主路由默认网关，需要接入的设备手动指定旁路 LAN 地址作为 DNS，或由主路由 LAN / DHCP 统一下发；主路由同时配置“FakeIP 网段 → 旁路 LAN 地址”静态路由。已有这条路由可以复用；新安装不能仅修改 DNS 而遗漏路由。不需要逐台设置终端网关或安装客户端。模式选择、来源识别、缓存和验收步骤见 [DNS 分流旁路](dns-bypass.md)。Mac mini 原生部署与 Linux 虚拟机的区别见 [macOS 部署](macos.md)。

## 首次登录及监听

所有管理 API（包括配置、订阅、日志、内核和服务）要求会话鉴权。默认监听 `127.0.0.1:9090`。升级后的第一次启动在数据目录写入 `setup-token`，权限为 `0600`，日志只打印路径。通过本机页面或 SSH 本地转发，输入该令牌并设置 12–72 字节的管理密码。密码只保存 bcrypt 摘要；初始化完成后删除令牌文件。会话 Cookie 为 HttpOnly、SameSite=Strict，HTTPS 时附加 Secure。默认会话 8 小时过期，重启管理器后需要重新登录；勾选「记住登录 30 天」后，关闭浏览器或重启管理器仍保持登录，最长 30 天（不自动续期）。只在自己的设备上勾选。长期会话只将 SHA-256 令牌摘要与到期时间写入权限为 `0600` 的 `auth.json`，不保存原始令牌；退出会撤销当前会话，改密会撤销全部会话。登录与改密尝试限速。

管理密码可以是自己好记的密码或短语，不需要每次输入初始化令牌。登录后可在「设置 → 管理密码」输入当前密码并设置新密码；成功后撤销所有设备的登录会话，需用新密码重新登录。改密单独保存，不依赖「保存所有设置」。登录和改密表单提供浏览器密码管理器所需的账号及自动填充字段（固定账号标识为 `admin`，无需手动输入账号），是否提示保存取决于浏览器设置。页面不把明文密码写入 localStorage/sessionStorage。

例如，远程管理使用 SSH 隧道：

```sh
ssh -L 19090:127.0.0.1:9090 user@gateway-host
# 浏览器打开 http://127.0.0.1:19090
```

需要直接监听 LAN 时，显式使用内置 HTTPS 和来源范围：

```sh
sbm -data /path/to/instance -listen 192.0.2.2 -port 9090 \
  -tls-cert /path/to/ip-certificate.pem -tls-key /path/to/private-key.pem \
  -allow-network 192.0.2.0/24
```

证书应对管理 IP 有效。Host 只接受 IP 或 localhost；不接受任意域名 Host，不信任 `X-Forwarded-*`。因此不要以未配置的反代 TLS 终止替代内置 HTTPS。回环来源始终允许进入认证流程，其他来源按可选 CIDR 列表限制。非回环明文监听在启动时被拒绝。不要把会话、订阅 URL 或节点密钥放入浏览器 URL。

## 策略与 DNS

普通设备推荐使用 `split`（普通分流）：保留国内直连、其他流量按规则选择出站的能力，结果取决于实际配置的自定义、预设和导入规则。`split` 不会额外生成覆盖全设备的代理规则。

| 设备策略 | 业务流量行为 |
| --- | --- |
| 普通分流 `split` | 继续匹配后续规则和最终出站；国内直连规则仍可命中 |
| 严格全代理 `strict` | 将经过实例的该设备业务流量送到指定代理出站，优先于国内直连等后续规则 |
| 直连 `direct` | 经过 sing-box 后使用直连出站 |
| 绕过 `bypass` | 绕过内核代理，使用网络层允许的直接转发路径 |

严格全代理是用户主动选择的整设备策略，不能用作普通分流或 WebRTC 保护的默认替代。DNS 分流旁路拒绝启用严格全代理设备，不会静默降级；上述严格策略语义继续用于完整网关，已有设备组的选择保留。完整网关严格组的业务流量及 DNS 都使用该组出站，并递归拒绝含 direct 回退或循环的选择组。允许的 LAN/排除网段是接管边界，不能填宽泛公网网段来绕过严格策略。DNS 旁路下，直连 / 绕过组优先返回真实地址并让连接经主路由；残留 FakeIP 到达实例时按来源走直连。

路由先执行协议嗅探和 DNS 处理，再执行显式的设备来源策略，随后处理 hosts、用户规则、预设规则组、导入规则和最终出站。用户规则按优先级数字从小到大排序，同级保持存储次序；导入规则保持原始相对次序。规则页中的实际生成次序用于核对这些层级。

一个规则内的来源、目的条件、TCP/UDP、嗅探协议、端口/范围联合匹配。空条件、非法端口、未知规则类型会被拒绝。网关拒绝远端进程/用户条件，不能把远端下载程序名称当作可识别进程。

需要限制浏览器可能使用的 STUN 时，可为工作电脑等指定来源设备增加独立联合规则，例如来源 `192.0.2.20/32`、嗅探协议仅 `stun`、出站选择代理或 `REJECT`。便捷设置将它排在当前其他自定义规则之前，因而也先于导入分流规则；此规则仍是可编辑的普通联合规则，手动调整优先级会影响匹配次序。它只针对可被嗅探识别的 STUN 流量，不会把所有网站、所有 UDP 或 BT/PT 一并强制代理。不能只靠固定端口推断 STUN，也不能保证识别全部 WebRTC 媒体或其他传输。设备策略和 hosts 有更高优先级；希望保留普通分流并保护 STUN 的设备应选择 `split`。

保护仅覆盖实际经过该实例的流量；设备默认路由、IPv6、备用网络或旁路直接出网仍需网络层配合。设备解释和生成配置展示配置预期，不冒充实时抓包结果。

单机和完整网关的 `proxy_dns`、`direct_dns` 实际进入 typed DNS 配置，支持 UDP、TCP、TLS、HTTPS、QUIC、HTTP3；域名型 DNS 通过明确的 bootstrap DNS 解析，避免递归。hosts 先匹配，随后是设备 DNS 策略、Split DNS、可映射的域名规则。含流量端口/协议的规则不会被错误扩大为全域名 DNS 规则。单机保留 FakeIP；完整网关默认使用真实 DNS 地址，兼容已有导入 DNS。DNS 旁路向 LAN 终端返回代理域名的 FakeIP；后续内部业务 `resolve` 查询使用 `proxy_dns` 获取真实地址。LAN 直连域名使用 `direct_dns` 或导入策略内相应解析器，节点引导和直连出站的显式默认解析器仍使用 `dns_direct`，避免代理解析循环。它按可安全映射的域名策略选择真实地址或 IPv4 FakeIP，并禁用共享 DNS 应答缓存以防来源差异污染；FakeIP 映射独立持久化。代理域名仅 A 返回 FakeIP，所有非 A 查询（包括 AAAA、HTTPS / SVCB、ANY、TXT、MX、SRV）均为 NOERROR 空答，避免地址提示绕行；hosts / 直连域名保留正常解析，需要 TXT / MX 等记录时须为相关域名显式直连或配置直连 Split DNS。路由器自身缓存或替代 DNS 仍可能绕过当前策略，须确认终端的实际 DNS 路径。无法安全转换的复杂导入 DNS 会阻止 DNS 旁路应用，导入原数据保留。

可选 DHCP 保留地址选择组后，会转换为对应 IP 的来源策略；与手动设备重复且同组时合并，冲突组拒绝保存。DHCP 默认关闭，root 策略还需独立授权。完整网络资源、冲突检查和恢复机制见 [Linux 网关部署](linux-gateway.md)。

## 配置和内核应用

“配置管理”提供脱敏的已应用/草案对比、只读草案校验，以及当前/前一版本的 SHA-256 摘要。规则页分别展示可编辑规则、导入规则、设备策略和完整路由次序；可编辑列表为空不代表内核没有规则。导入规则保存为独立策略，已保存的草案也不等于已应用配置。已应用视图来自运行配置文件；即使文件存在，仍需结合内核运行状态判断是否正在处理流量。

所有手动和自动配置应用共用：候选私有临时文件 → `sing-box check` → 私有备份 → 同目录原子切换 → 对原本运行中的实例重启和健康检查 → 失败恢复。原本停止的单机实例只更新配置，不自动启动；显式启用网关则启动并验证内核。

DNS 旁路显式停止内核时会一并恢复 helper 资源、关闭 `Gateway.Enabled`，保持进程停止；再次使用须重新检查并启用。异常退出仍保留所属记录供状态检查和恢复，不能视为已自动撤回资源。完整网关原有停止与严格策略语义保持不变。

健康检查包含进程身份、稳定窗口及已配置 Clash API 的本地版本响应，不代表外网节点、UDP 转发或客户端覆盖验收。旧版本恢复要求摘要仍匹配且监听/接管方式相同；恢复后关闭自动应用，草案保留，避免下一次订阅刷新立即覆盖恢复结果。配置备份为 `config.json.previous`，不是长期无限版本仓库。

内核更新先验证候选版本和当前配置；旧内核保留为 `sing-box.previous`。替换、重启、健康及失败恢复与配置共用生命周期锁。家庭网关要求可识别的 1.14 或更新 1.x，生成字段基于 1.14 能力，不生成 1.15 专属 TUN 字段；真正切换前仍由目标二进制校验。内核下载成功不等于部署验收。

管理器按数据目录排他锁拒绝重复启动；跟踪 core 同时核对可执行文件、唯一配置参数、cwd 和进程创建时间，不按名称抓取第一个进程。管理器退出保留受管 core 与独立脱敏日志中继，后续管理器只恢复匹配身份的实例。

## sing-box 配置导入

配置管理中的“导入配置”接受任何来源的最终 sing-box JSON，也兼容对象或 JSON 字符串形式的 `config` 包装。Clash YAML/Base64 订阅仍在订阅管理中添加；此处不解析第三方面板数据库。先预览，再用同一内容摘要确认导入：

- 原节点及其协议字段、选择组成员、路由次序/来源/端口条件、DNS/hosts、自定义出站和规则集保留。
- 旧格式的 `source_ips` 作为兼容适配转为 `source_ip_cidr`；用户已有节点/出站标签及其引用不改名。为避免管理器保留命名冲突，`dns_` 前缀的导入 DNS 标签统一加 `imported-` 前缀，同步更新包括 `resolve` 路由在内的引用。
- 旧入站、管理端口、TProxy/TUN 接管和日志等明确列为不导入项，需要确认。未知顶层/路由语义、旧 DNS 格式、宿主文件依赖、旧 inbound 匹配等会阻止导入，不能静默丢弃。
- 导入前完整数据保存在 `migration-before.json`，文件名保留以兼容已有恢复点。导入替换当前导入策略，并清空原可编辑规则、预设规则组和筛选组；原草案完整留在恢复点中，导入页会明确提示并要求确认。导入只保存单机草案，关闭自动应用和 TUN，运行配置与其他实例不受影响。导入后的订阅/手动节点通过 `Managed Proxy` / `Managed Auto` 及自定义规则使用；原选择组成员保持原样，标签冲突明确报错。
- 并行验证使用独立数据目录和 mixed/管理/Clash 端口；不同实例不得同时接管路由或监听同一端口。预览经过脱敏，不能作为可运行配置导出；保管好原始配置和私有备份。

通用入口为 `/configuration/import`，API 为 `/api/config/import/preview`、`/api/config/import/apply`、`/api/config/import/rollback`。旧 `/migration` 页面和 `/api/migration/*` 调用保留为兼容别名，既有导入数据和恢复点继续使用，无需重新导入。

确认配置和冲突检查后，在隔离网络或维护窗口逐项验证 TCP、UDP、IPv4、IPv6、真实 IP、DNS、内网访问、普通分流的国内直连和 BT/PT 出站，演练 DNS / 路由回退，再扩大范围。DNS 旁路通过主路由 DHCP 统一下发 DNS，终端网关保持不变；完整网关需要默认路由经过本机。Docker bridge NAT 隐去容器来源时，需给下载容器独立可识别地址/网络或单独出网路径；监听端口不能代表所有对端端口，也不能据此放行整台宿主机。

## 开发验证

```sh
go test ./...
go test -race ./...
go vet ./...
npm --prefix web run build
# 使用从官方发布下载到隔离目录的二进制，只做配置验证，不启动代理
SBM_TEST_SINGBOX=/isolated/path/sing-box go test ./internal/builder -run TestRealKernelGeneratedConfigurations -v

# 真实 DNS 引擎在回环高端口运行；禁用 TUN/TProxy，不改宿主路由
SBM_TEST_SINGBOX=/isolated/path/sing-box go test ./internal/builder -run TestRealKernelDNSBypassAnswersAndRestart -v
```

Go 测试与前端构建用于代码验证。实际内核配置检查需要指定目标二进制；非 Linux 环境的网关 `format` 只能验证解析，不能代替 Linux `check`。真实 Linux namespace 测试需要独立 Linux/root 环境并显式启用，见网关文档。自动化检查不代替浏览器、Mac launchd/TUN、Linux 数据包转发或真实网络验收。
